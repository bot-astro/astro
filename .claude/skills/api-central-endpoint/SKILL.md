# services/api-central

Package `space.astro.api.central`. Spring Boot MVC (blocking) service on top of `shared:core`. Never touch `central-api-old`; use it only as a behaviour reference.

## Adding an endpoint
1. Add the path const to `CentralApiEndpoint` in shared/core (`/v2/...`, `{guildId}` style vars).
2. Controller in `controllers/` (`guild_settings/` for per-guild settings). `@RestController` with constructor-injected repositories/clients/services. Map with `@PostMapping(CentralApiEndpoint.X)` etc.
3. Return `ResponseEntity<T>`. Guild settings endpoints return the whole updated `GuildSettingsEntity`.
4. Guild-scoped endpoints: add `@CanManageGuildMiddleware` (needs a `guildId` path variable; checks Discord perms via `GuildPermissionsHelper`). Put it on every mutating guild endpoint, including DELETE.
5. Load guild settings with `guildSettingsRepository.findByIdOrNull(guildId) ?: throw ANotFoundException("Guild with ID $guildId not found in Astro database")`, mutate, `save`, return.
6. Calls to the bot go through `BotApiClient`; Discord REST through `DiscordApiClient`. Don't build HTTP calls in controllers.
7. Premium limit checks are not ported, leave a `// TODO` if relevant.

## Request bodies
- Data class in `models/requests/` named `XCreateBody`/`XUpdateBody` (responses in `models/responses/`).
- Implement `Validatable` (from shared/core) for user input: `ValidationResult.combine(...)` with `asValidationResult(msg)`. `ValidatableControllerAdvice` calls it automatically after body read and throws a 400. Reusing a shared-core model (e.g. `GeneratorSettings`) as the body works too if it is `Validatable`.
- Multipart: `@RequestPart("meta")` + `@RequestPart("media") MultipartFile` (see `MediaController`).

## Errors
Just throw `AException` subclasses; `ControllersExceptionHandler` maps them (and Spring/security exceptions) to `AErrorResponse`. Don't catch to build error responses manually. Exception: rate-limit responses that need `Retry-After` (see `MediaController`). Filters use `writeException`.

## Auth
- Session cookie auth: `AuthFilter` -> `AuthContext`/`AuthPrincipal` (`models/auth/`), sessions in Redis via `AuthSessionService`. Kube lifecycle endpoints use `KubeAuthFilter`. Route rules live in `components/security/SecurityConfig.kt`; check it when adding a public or special-auth route.
- Get the current user from `AuthPrincipal` (`userId`), not from request params.

## Rate limiting
- Global per-IP/per-user limits are filters in `components/security/ratelimit/` (don't modify per endpoint).
- Endpoint-specific limits: add a `resolveXBucket(key)` to `RateLimitingService` using `proxyManager.getProxy(RedisKey.RATE_LIMIT("namespace", key)) { BucketConfiguration... }`, then `tryConsumeAndReturnRemaining(1)` in the controller.

## Services and components
- Business logic with state/IO that isn't a plain repo call goes in `services/` (`@Service`, e.g. `MediaStorageService`, `OAuthStateService`). Cross-cutting Spring beans (advice, config, helpers) in `components/`.
- New config: `@ConfigurationProperties` in shared-core `properties/api_central/` (auto-scanned) or listed in `Application.kt` `@EnableConfigurationProperties` if shared; add keys to `src/main/resources/application.yml`.

## Docs
OpenAPI/Scalar are generated by springdoc from the controllers (`/docs`); use plain Spring annotations, add `@Operation` only if needed.
