# shared/core

Base package `space.astro.shared.core`. Library module shared by `bot` and `api-central`; everything is wired via Spring Boot autoconfiguration, not component scanning. Never touch `shared/old-core`.

## Mongo entity + repository
- Entity in `models/database/` (`@Document(collection = "...")`, data class, `@Id val id: ObjectId = ObjectId.get()`, `@Indexed` on lookup fields). Nested settings data classes live in a subpackage (`guildSettings/`, `userSettings/`).
- Repository in `repositories/mongo/`: `interface XRepository : MongoRepository<XEntity, String>` with derived queries (`findAllByGuildId`). Default methods on the interface are fine for small helpers (see `GuildSettingsRepository.createNewGuildSettings`).
- Already picked up by `@EnableMongoRepositories(basePackages = [...repositories.mongo])` in `AMongoRepositoriesAutoConfiguration`. Nothing to register.

## Redis
- Keys go in `utils/redis/RedisKey.kt` as functions on the `RedisKey` object (`fun AUTH_SESSION(userId, sessionId) = "AT:$userId:$sessionId"`). Short unique prefix, never inline key strings elsewhere.
- Redis-only entities (no `@Document`, e.g. `TemporaryVCEntity`) get a `@Repository class` in `repositories/redis/` wrapping `StringRedisTemplate` + `JsonMapper` (see `TemporaryVCRepository`, built on `RedisDynamicHashCacheRepository`).
- Redis repos are registered by `ARedisRepositoriesAutoConfiguration`; check it when adding one.

## Validation
- Anything validated from user input implements `Validatable` and returns `ValidationResult`:
  `(cond).asValidationResult("message")` per field, then `ValidationResult.combine(a, b, ...)` (first failure wins). Messages are lowercase-ish user-facing sentences.
- `validate()` may normalize fields (see `GeneratorSettings` computing `ownerPermissions`). Snowflakes: `String.isValidSnowflake()`.
- api-central runs `validate()` automatically on `@RequestBody` types, so don't call it in controllers.

## Exceptions
- Throw `AException` subclasses from `exceptions/AException.kt`: `ABadRequestException` 400, `AUnauthorizedException` 403, `ANotFoundException` 404, `AUnknownException` 500. New status/code combos: add a value to `AErrorCode` and a subclass. The api turns them into `AErrorResponse(code, message)`.

## API endpoint constants
- Every HTTP path lives in `utils/api/CentralApiEndpoint.kt` (central API, `/v2/...`) or `BotApiEndpoint.kt` (bot API, `/api/v2/...`) as `const val` with `{pathVars}`. Controllers and clients must reference these, never literal paths.

## Bot / Discord clients
- `clients/BotApiClient.kt` (central -> bot over RestClient) and `DiscordApiClient.kt`. Request/response DTOs in `models/api/bot/{request,response}/`; Discord DTOs in `models/discord/`.
- Client method pattern: `client.<verb>().uri(baseUrlForGuild(guildId) + BotApiEndpoint.X, vars...).retrieve().body() ?: throw AUnknownException(...)`, wrapped in `try/catch (e: RestClientException)` mapping 404 -> `ANotFoundException`, anything else -> `AUnknownException("Failed to ...", e)`.

## Properties
- `@ConfigurationProperties("prefix") data class` in `properties/` (kebab-case keys in yml map to camelCase fields). Service-specific ones go in `properties/<service>/` (e.g. `api_central/`) and are found by that service's `@ConfigurationPropertiesScan`. Shared ones must be listed in the service's `@EnableConfigurationProperties` in `Application.kt`.
- Add the matching keys (with `${ENV_VAR}`) to the service's `application.yml`.

## Autoconfiguration
- New beans = new `@AutoConfiguration` class in `autoconfigure/` (`A` prefix, `@ConditionalOnProperty`/`@ConditionalOnMissingBean` as appropriate) AND a line in `resources/META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports`.

## i18n
- Strings in `resources/i18n/<tag>.json` (flat `key -> ICU MessageFormat`). Use `L.t(locale, "key", "arg" to value)`; missing keys fall back to `en-US`, then throw. New locale = new json file (index generated by gradle, no code change). Guild locale is `GuildSettingsEntity.javaLocale`.

## Style
Kotlin, ktlint/detekt (trailing commas, multi-line params one per line). Premium checks are intentionally not implemented, leave a TODO.
